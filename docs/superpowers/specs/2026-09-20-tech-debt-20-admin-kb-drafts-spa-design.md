# Tech Debt #20 — Admin KB Drafts SPA UI

> **Status:** design approved (M3 kickoff). Implementation plan: `docs/superpowers/plans/2026-09-20-tech-debt-20-admin-kb-drafts-spa.md` (TBD).

## Goal

Ship a review UI in the existing `apps/web/` agent SPA for the admin KB-draft endpoints (`/api/v1/admin/kb-drafts`). Admins (and owners) can list, view, approve, and reject drafts generated by the history-mining worker.

## Context

The backend for KB-draft review already exists (`apps/api/src/admin/api.py`, Stage 18 / M2.B Task 8). After tech debt #17 lands, those endpoints will be JWT-gated with `Depends(require_admin)` returning 401/403 for non-admins. The frontend SPA at `apps/web/` is a React 18 + Vite + TypeScript app with `react-router-dom@6`, `@tanstack/react-query@5`, axios, zod, Tailwind, Radix UI primitives, lucide-react icons. Pattern is established: every page has a Zod schema in `lib/<domain>.ts`, a page in `pages/<domain>.tsx`, components in `components/<domain>/`, and tests in `__tests__/<file>.test.{ts,tsx}`. Sidebar nav lives in `components/layout/app-shell.tsx`.

The `grep` for `kb-drafts` across `apps/web/src` returns zero matches today — no page, no API client function, no nav entry exists.

## Approach

**Add a new route `/admin/kb-drafts` inside the existing SPA, gated by a new `AdminGuard`.** Reuse `AuthGuard` for the JWT check, add `AdminGuard` for the role check. Sidebar shows the "Admin → KB Drafts" entry only when `claims.role` is `admin` or `owner`.

### File-level changes

#### `apps/web/src/lib/kb-drafts.ts` (NEW)

Mirrors `lib/knowledge.ts` exactly. Exports:

```typescript
export const KbDraftSchema = z.object({
  id: z.string(),
  title: z.string(),
  body_preview: z.string(),
  tags: z.array(z.string()),
  source_question_count: z.number().int().nonnegative(),
  cluster_id: z.number().int().nullable(),
  status: z.enum(["DRAFT", "APPROVED", "REJECTED"]),
  created_at: z.string(),  // ISO 8601
});

export const KbDraftDetailSchema = KbDraftSchema.extend({
  body: z.string(),
  reviewed_at: z.string().nullable(),
  reviewed_by: z.string().nullable(),
});

export const KbDraftListSchema = z.object({
  drafts: z.array(KbDraftSchema),
});

export async function fetchDrafts(params: {
  status?: "DRAFT" | "APPROVED" | "REJECTED";
  limit?: number;
} = {}): Promise<KbDraftListSchemaType> { ... }

export async function fetchDraft(draftId: string): Promise<KbDraftDetailSchemaType> { ... }

export async function approveDraft(draftId: string): Promise<{ draft_id: string; article_id: string; status: "APPROVED" }> { ... }

export async function rejectDraft(draftId: string): Promise<{ draft_id: string; status: "REJECTED" }> { ... }
```

Each function uses `apiClient.get/post` (the existing axios instance from `lib/api-client.ts` — already auto-attaches the JWT).

#### `apps/web/src/components/auth/use-current-user.ts` (extend existing)

Add a derived hook `useIsAdmin()` that returns `claims.role === "admin" || claims.role === "owner"`. The existing `useCurrentUser` already exposes `claims`; `useIsAdmin` is a thin wrapper.

#### `apps/web/src/components/auth/admin-guard.tsx` (NEW)

```typescript
export function AdminGuard({ children }: { children: React.ReactNode }): JSX.Element {
  const { claims, isLoading } = useCurrentUser();
  if (isLoading) return <FullPageSpinner />;
  if (!claims) return <Navigate to="/login" replace />;
  if (claims.role !== "admin" && claims.role !== "owner") {
    return <Navigate to="/inbox" replace />;
  }
  return <>{children}</>;
}
```

Mirrors `components/auth/auth-guard.tsx` exactly.

#### `apps/web/src/pages/admin-kb-drafts.tsx` (NEW)

Page shell using the `kb.tsx` page as the model:
- `useQuery({ queryKey: ["kb-drafts", status], queryFn: () => fetchDrafts({ status }) })`
- Tab strip for status filter: `DRAFT` (default) / `APPROVED` / `REJECTED`
- `useMutation` for `approveDraft` / `rejectDraft` with `extractErrorMessage`
- Renders `<DraftList drafts={data.drafts} />`

#### `apps/web/src/App.tsx` (lines 17–28)

Add inside the `AuthGuard` block:
```tsx
<Route element={<AdminGuard><AppShell /></AdminGuard>}>
  <Route path="/admin/kb-drafts" element={<AdminKbDraftsPage />} />
</Route>
```

(Important: `AdminGuard` is a **separate** route element from the regular `AuthGuard` block — admins can still visit `/inbox` etc., but only `AdminGuard`-wrapped routes are gated on role. Pattern is parallel to the existing `AuthGuard` block.)

#### `apps/web/src/components/layout/app-shell.tsx` (or sidebar component)


## Multi-tenant isolation

The JWT carries `tenant_id`. The axios interceptor already attaches the bearer token. The backend (`admin/api.py` after tech debt #17) reads `tenant_id` from claims and filters by it. The SPA never constructs or sends a `tenant_id` parameter. No new surface for tenant leakage.

## PII discipline

The list endpoint returns `body_preview` (200 chars) — already cropped server-side. The detail dialog shows the full body but only after a successful admin JWT auth. `source_questions` is NOT exposed via the API (it's an opaque ULID list per the backend docstring), so the SPA has no way to display raw customer text — admins see the LLM-generated body only. No new PII surface.

## Out of scope

- Bulk approve/reject
- Inline edit of draft body before approving (would require a new backend endpoint)
- Notifications when new drafts are generated (out-of-band worker)
- Sorting / advanced filtering (status tab is enough for v1)
