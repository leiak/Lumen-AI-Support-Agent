# Demo docs (Stage 9.12)

This directory holds the M1 end-to-end demo materials.

## What's here

| File                                  | Purpose                                                                |
| ------------------------------------- | ---------------------------------------------------------------------- |
| `docs/demo-script.md`                 | The 12-15 min three-act demo script. Read this for the full walkthrough. |
| `docs/sample-docs/new-feature.pdf`    | A 2 KB sample PDF used in Act 3 (admin KB upload). Generated by reportlab. |

## Who should read this

- **Stakeholders / sales engineers** — read [`demo-script.md`](./demo-script.md) top to bottom before a customer walkthrough.
- **New engineers onboarding onto M1** — skim the **Environment setup** and **Closing** sections; cross-reference the routes/credentials listed there with the source.
- **Demo presenter** — keep `demo-script.md` open during the recording; the **Troubleshooting** section is your safety net.

## 30-second version

1. **Act 1** — customer types "How do I reset my password?" into the Web Widget embedded on `tests/e2e/static/widget-host.html`. AI answers from the Acme KB, then the customer hits **需要人工** to escalate.
2. **Act 2** — agent logs in at `http://localhost:5173/login` as `agent@demo.test`, claims the PENDING conversation, asks the AI for a suggestion, edits it, and sends.
3. **Act 3** — admin logs in as `admin@demo.test`, opens `/kb`, uploads `docs/sample-docs/new-feature.pdf`, watches `draft → indexing → indexed`, then inspects `/settings` for the channel list.

Credentials (seeded by `tests/e2e/scripts/seed.py`): both `agent@demo.test` and `admin@demo.test` use password `Demo123!`. Treat them as ephemeral — never ship to production.
